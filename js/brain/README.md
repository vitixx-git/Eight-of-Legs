# BRAIN_HALL — «Голова изнутри»

Рабочая **процедурная версия**, а не подтверждённая сборка с исходными GLB.

## Запуск

Из корня проекта:

```sh
python -m http.server 8000
```

Открыть `http://localhost:8000/tools/brain_preview.html`. Не открывать HTML через `file://`: загрузка ES-модулей и ассетов требует HTTP.

`index.html` остаётся исходной игрой с заглушкой S03. Настоящие S03_Meet, C_Levers, battleCore и ui/cockpit.js в предоставленном архиве отсутствуют; новая сюжетная логика вместо них не сочинялась.

## Что есть в сборке

- Общая расстановка в `layout.js`, декор в `furnish.js`, адаптер событий в `sceneAdapter.js`.
- Бордово-розовая органика, тёмно-фиолетовая техника, переход света в янтарь на 14–16,5 с.
- 18 типов приборов представлены процедурными заменами, которые явно помечены в предпросмотре и результатах запекания.
- Сидированные стеновые пульты: кнопки, тумблеры, крутилки, ползунки, LED, экраны и таблички. Всего 10 InstancedMesh-пакетов, включая контур корпусов. Подписи и 8 типов экранов объединены в один атлас, чтобы не превышать бюджет вызовов.
- Раскрытие экрана «ГЛАЗА» за 0,6 с, изображение спальни через RenderTarget 256×160 / 15 Гц, искажение и сканлайны.
- Перфорированная движущаяся лента между рулоном и модемом; мигание модемов; пузырьки котла; шторки; ядро; книги; закрывающийся ящик.
- Звук будильника в предпросмотре синтезируется Web Audio после первого нажатия пользователя. В игре звук вызывается через `onAlarm`, без вмешательства в общую аудиосистему.
- Режим пониженной детализации после трёх секунд FPS < 50: книги 6 → 3, лампы 2 → 1. Для загруженного GLB будильника предусмотрен SimplifyModifier 0,5; реальная модель не предоставлена, поэтому эта ветка не принята по результату.

## Подключение к существующей сцене

```js
import {attachBrain} from '../brain/sceneAdapter.js';

// enter: root — непосредственный ребёнок THREE.Scene.
this.brain = await attachBrain({
  root: this.root,
  eventTarget: this.root,
  config: cfg.brain,
  eyeView: () => ({scene: bedroom.scene, camera: bedroomEyeCamera}),
  onAlarm: () => audio.play('WAKE_ALARM')
});

// update: использовать логическое время; не вызывать на паузе.
this.brain.update(dt, {
  spiderPosition: spider.group.position, // координаты в root
  leversTime: timeline,
  fps: measuredFPS
});

// Перед основным renderer.render:
this.brain.render(renderer);

// exit:
this.brain.dispose();
```

Вместо `leversTime` можно посылать события `C_Levers:time` с `time` либо `detail.time`. Состояния: событие `brain:state`, `state` либо `detail.state`: `sleep`, `waking`, `amber`. Предпросмотр «ПРОБУЖДЕНИЕ» показывает состояние на 12-й секунде. Реальный таймлайн остаётся у владельца сцены.

Существующие BRAIN_FLOOR, BRAIN_DOME, NERVE_TUBE_0…5, NEURONS, CONSOLE_BARRIER и COCKPIT_PANEL переиспользуются. Сам адаптер не создаёт защитников и не меняет их сюжетные позиции. Предпросмотр добавляет их отдельно. Для корректного скрытия любых дополнительных актёров при запекании: `actor.group.userData.brainActor = true`.

## Как подключить настоящий brain_kit

В переданном архиве нет `assets/brain_kit/models/*.glb` и `brain_kit_manifest.json`. Это не исправляется переименованием процедурных объектов в GLB.

1. Добавить исходный манифест и модели по указанным в нём путям.
2. Установить `available: true` в `assets/brain_kit/availability.json` либо передать `manifest` в `furnishBrain` / `attachBrain`.
3. Проверить 18 строк отчёта: `status: loaded`. Ошибки конкретных моделей показываются в `error` и `brain.issues`.
4. Проверить по реальным материалам `rotY`, `recolor`, узлы стрелок, шторок и молоточка. Автоматическое совпадение неизвестных имён не гарантируется.

Общий загрузчик `js/kit/kitLoader.js`: масштаб по целевой высоте/ширине/горизонтальной длине; центр XZ и низ Y; усреднение текстур; toon-материалы; кэш. Официальные GLTFLoader, SimplifyModifier и BufferGeometryUtils r170 приложены локально. Draco/KTX2/Meshopt-декодеры не приложены: наличие сжатых ассетов потребует их отдельного подключения. Исходные GLB не исследованы.

## Запекание и готовые PNG

```js
import {bakeArena2D} from './bakeArena2D.js';
import {bakeCockpit2D} from './bakeCockpit2D.js';

const arena = await bakeArena2D(renderer, brain, 'REFLEX');
const cockpit = await bakeCockpit2D(renderer, brain);
```

`brain` здесь — результат `furnishBrain`, либо `this.brain.brain` из адаптера. Возвращается `{canvas, ms, draft, variant, cacheKey}`. Без renderer есть процедурный fallback. Можно заранее вызвать `prepareBakes(renderer, brain)` из `bake.js`, чтобы отдельно подготовить шейдеры; время этой подготовки не следует скрывать при замере холодного запуска.

В `assets/brain_baked/` приложены 3 арены 960×540 и кабина 352×220 с суффиксом `_DRAFT`: они запечены из процедурных замен, не из отсутствующего набора.

Арена: камера 55°, 5,11 px/см, центр (480,300). Скрыты персонажи, барьер, пульт с креслом, знаки, скамейка, ядро, книги и верхняя органика. Для нижних сегментов высота ограничивается при запекании; дополнительная экранная маска не допускает декор внутрь игровой эллиптической области r 230. Кольцо арены в PNG не рисуется.

Кабина: кресло, персонажи, барьер, рычаги и перекрывающие приборы знаки скрыты; «ГЛАЗА» тёмный; освещение янтарное, светофоры зелёные. Совпадение с отсутствующим ui/cockpit.js не проверено.

Рендер выполняется ×2 и уменьшается. Кэш зависит от seed/density/настроек и поколения генератора; повторное получение возвращает тот же объект. Запекание использует фиксированное логическое время 0 для воспроизводимости, затем восстанавливает исходные время, таймлайн, видимость, материалы, свет, матрицы, фон и параметры renderer. Звук во время запекания подавлен.

## Честные ограничения

- Приёмка 18 оригинальных GLB, анимаций набора и бюджета с ними невозможна без набора.
- Не подтверждены интеграция и сохранность отсутствующих сюжетных сцен, ракурс отсутствующего UI кабины и звук в настоящей игре.
- У инстансированных пультов отдельный hull-контур есть у корпусов; у каждого маленького органа управления индивидуальный hull не добавлялся. Это ограничение полного стилистического соответствия ТЗ, а не подтверждённая приёмка всех обводок.
- Метка «10 вызовов» относится к стеновым пультам, а не ко всей процедурной сцене.
- FPS ≥55 на среднем ноутбуке не подтверждён. Проверка в удалённом Chromium с программным WebGL не является тестом пользовательского GPU.
- Конкретные измерения и статусы по 7 пунктам — в `BRAIN_HALL_ОТЧЁТ.md` в корне проекта.
