# ROOM_LAB — модуль лаборатории

Запуск из корня: `python -m http.server 8000`, открыть `/tools/lab_preview.html`.
Локальные библиотеки Three.js r170, внешние сервисы не нужны. Дополнения загрузчика: `python tools/cache_lab.py`.

## Входные ресурсы

`assets/lab_kit/lab_kit_manifest.json` пока является **шаблоном**, `pendingAssets: true`. Все 17 GLB отсутствуют. Их геометрия, лицензии, ориентация и точные метаданные не выдумываются. После добавления реального набора заполнить манифест и убрать pendingAssets. Превью без GLB показывает яркую процедурную мастерскую с явно обозначенными заменами декора; маркеры отсутствующих GLB можно включить отдельно. Фоны такого состояния помечаются DRAFT.

## Подключение (в проекте пока нет игровых сцен)

```js
import {furnishLab} from './js/lab/furnish.js';
const lab=await furnishLab(roomRoot,'live',{scene:'S10',duration:60});
// В игровом цикле: lab.update(dt). Во время паузы не вызывать.
// Существующий автомат S10 сам уведомляет декор:
lab.setState('stopped'); // либо roomRoot.dispatchEvent({type:'stopped'})
lab.setState('destroyed');
// Режим воспоминания:
lab.setMode('memory');
// На выходе: lab.dispose();
```

Имеющиеся именованные процедурные объекты сохраняют позиции; модуль создаёт только отсутствующие. Модуль не реализует и не заменяет автомат S10, перенос контейнера, падения или контрольные точки. Коллайдеры декора доступны в `lab.colliders` — сцена должна добавить их в свою систему. Проходимость без капсулы и исходников S07/S10 не подтверждена. Если геометрия существующих объектов отличается, требуется согласовать декор после подключения.

`layout.js` хранит позиции и конфигурацию загрузки. `kitLoader.js` кэширует по URL и конфигу, нормализует, заменяет текстуры усечённым средним цветом, упрощает однородные меши, запекает Spider_Death и удаляет кости. Меши с несколькими материалами не упрощаются: SimplifyModifier не сохраняет группы; фактический бюджет нужно проверить на наборе. `rotY` задаёт поправку исходной модели перед нормализацией; поворот размещения задаётся отдельно.

`bakeLab2D(renderer, variant, options)` возвращает `{canvas, draft, fallback, ms}` и кэширует Promise по варианту/конфигу. `renderer=null` включает Canvas 2D. Запекание временной сцены в 3840×2160 с уменьшением до 1920×1080; MEMORY добавляет тон и виньетку. Сохранение PNG — кнопками скачивания, а не автоматическая запись в assets. Кэш в памяти текущей страницы, не на диске.

## Оформление мастерской

Возвращено оформление в духе «Фиксиков»: бирюзовые стены, сине-оранжевая мебель, жёлтые трубы, манометр, вентиль и панель инструментов. `workshop.js` добавляет оригинальный процедурный декор и замены отсутствующих GLB. Длинная ручка швабры убрана, ведро оставлено. Расстановка, состояния и запекание сохранены; запасной Canvas 2D использует яркую палитру. Персонажи не менялись.

## Ограничения приёмки

Нет реального набора, игровых сцен и полного §8.4. Не подтверждены лицевая ориентация GLB, отсутствие дыр после упрощения, крепление экрана к реальному монитору, оси часовых стрелок и зелёный индикатор анализатора, зазоры 20 см, проходы, камера и надпись с камерой S10. Нельзя подтвердить 55 FPS на среднем ноутбуке измерением на другой машине. Превью и черновые фоны не являются завершённой интеграцией игры.
