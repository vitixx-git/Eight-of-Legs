# HOUSE — процедурный прототип

## Статус

Оригинальных `assets/house_kit/models/*.glb`, манифеста и настоящих сцен S07_Morning, C_Wardrobe, S08_Prep в предоставленном проекте нет. Поэтому поставка — самостоятельный предпросмотр с 24 процедурными типами мебели, а не завершённая интеграция оригинального набора. Демонстрационные стены, лестница и игровые предметы не подменяют отсутствующие сюжетные сцены.

## Запуск

Из корня проекта: `START_HOUSE.bat` (Windows с Python 3) или `python launch_house.py`. Сервер привязан к 127.0.0.1, выбирает порт 8010–8019 и открывает `/tools/house_preview.html`.

Ручной запуск: `python -m http.server 8000`, затем `http://localhost:8000/tools/house_preview.html`. Не открывайте HTML через file://. `/index.html` оставлен исходной игрой.

Для проверки Canvas-режима добавьте `?fallback=1`.

## Файлы

- `layout.js`: сантиметры, локальные комнаты, расстановка, rotY/recolor, явно демонстрационные защищённые зоны.
- `props.js`: 24 процедурных типа (не GLB), мебель и небольшие предметы.
- `room.js`: прототип архитектуры и лестницы, процедурные игровые предметы только для демо.
- `furnish.js`: `await furnishRoom(roomId, root, options)`; принимает HALL/HALL_GROUND, BATH/BATH_ROOM, STUDY/STUDY_ROOM, LIVING.
- `kitLoader.js`: переэкспорт общего `js/kit/kitLoader.js`, GLTFLoader и единый кэш исходников. Реальные модели не были доступны для испытания.
- `dollhouse.js`: сборка тех же комнат в дом и освещение.
- `bakeHouse2D.js`: RT 3840×2160 → PNG 1920×1080, день/ночь, кэш на экземпляр дома и конфигурацию, projected hotspots и Canvas fallback.
- `sceneAdapter.js`: заготовка подключения к существующей комнате без создания оболочки. Автоматически никуда не подключена.

## API

```js
import {furnishRoom} from './js/house/furnish.js';
const furniture = await furnishRoom('STUDY_ROOM', roomRoot, {
  buildShell: false,
  config: houseConfig,
  // useKit: true, // включать только после получения и проверки реального набора
  protectedPoints: [passCardLocalPosition, coffeeLocalPosition]
});
furniture.update(seconds, sceneProgress); // progress 0…1
furniture.setOcclusionHeight(humanHeight + 80);
// furniture.colliders: локальные AABB, по X/Z ужаты на 2 см
// furniture.pushChair(10): демонстрационный сдвиг по +Z, сохранение поперечного прохода
// furniture.refreshColliders(); furniture.dispose();
```

`buildShell:false` не создаёт стены, DESK и другие процедурные игровые опоры и не создаёт/не перемещает NOTEBOOK или KEYS. Их синхронизация с сиденьем и верхом комода в настоящих сценах должна выполняться владельцем геймплея. Объекты PASS_CARD/MUG читаются с настоящих позиций, если они есть; можно передать локальные protectedPoints явно. Декор не имеет права двигать эти предметы. В прототипе два элемента стола сдвинуты для свободных зон; после получения реальных сцен их зазоры надо проверить заново.

Для загрузки подготовьте манифест (массив или `{models:[...]}`) и `models/*.glb`. В entry.file путь относительно `assets/house_kit/house_kit_manifest.json`. `useKit:true` намеренно не скрывает отсутствие самого манифеста. Ошибка отдельной модели видна в issues, используется процедурная замена. Ориентации настоящих моделей, их материалы, стрелки и поверхности НЕ откалиброваны без набора; пол в прототипе — инстансы процедурного тайла. Нельзя считать подключение набора принятым только из-за наличия загрузчика.

## Ограничения относительно исходного задания

- Кадр разреза расширен до **1680×945 см**, а не 1450×815,6. Дом шириной около 980 см, с карнизом около 1035 см, не помещается в правые 65% от 1450 см (942,5 см). Асимметричная ортографическая рамка сохраняет пустые левые 35% и дом целиком. Взгляд (-159,378,0), наклон 8° сохранены. Hotspots вычислены для этой камеры.
- В предпросмотре комнат используется демонстрационная камера, не неподтверждённая камера отсутствующих S07/S08.
- Для читаемости разреза добавлен мягкий фронтальный заполняющий свет. Солнце и полусферический свет используют палитру задания.
- Ближняя боковая стена скрывается при осмотре комнаты. Существующая камера реальной игры не меняется.
- PASS_CARD, кружка, NOTEBOOK, KEYS, кошачья зона и препятствия лестницы в демо — демонстрационные. Кошка/учёный/паук не запекаются.
- Кнопка/клик hotspot выбирает комнату в предпросмотре и показывает плановый маршрут; не запускает отсутствующую настоящую сцену.
- Кэш живёт в памяти страницы, инвалидируется пересборкой/правкой расстановки. Между перезапусками уже готовые PNG можно брать с диска. Сохранения в localStorage/IndexedDB нет.
- Время первого запекания зависит от WebGL и компиляции материалов. ≤2 с не гарантируется; см. фактический отчёт. FPS55 не подтверждён на среднем ноутбуке.

## Экспорт

Готовые файлы: `assets/house_baked/SPR_HOUSE_BG_DAY_DRAFT.png`, `SPR_HOUSE_BG_NIGHT_DRAFT.png`, `SPR_HOUSE_BG_FALLBACK_DRAFT.png`, `SPR_HOUSE_BG_hotspots.json`. DRAFT — сознательная пометка процедурного происхождения, не финальные спрайты набора. Hotspots измеряются в координатах 1920×1080 независимо от CSS-масштаба.

В интерфейсе кнопка «Запечь день / ночь» показывает результат и отдельные кнопки скачивания. Наложение hotspots — только поверх предпросмотра, в скачиваемый PNG не попадает. При запекании восстанавливаются видимость комнат/стен, освещение, время/углы часов, прозрачность, render target, viewport, scissor и autoClear.
